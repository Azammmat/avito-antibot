# Avito Antibot — Bot Detection Challenge

Классификация кук на ботов (сервисы автоматизированного сбора данных) и людей по событиям внутри суточного окна.
Для каждой `cookie_id` модель выдаёт `score` ∈ [0, 1]; чем выше, тем вероятнее бот.

**Результаты**

- Скрытый тест (по данным проверяющей системы): **Precision@Recall≥0.70 = 0.88798**.
- Временная кросс-валидация на train (считается в `solution.ipynb`): средний P@R≥0.7 = **0.8095** по 3 фолдам.

Полное описание подхода также приведено в последней ячейке `solution.ipynb`.

## Подход

**Очистка событий.** Точные дубликаты удаляются, `platform` нормализуется (`desktop`→`web`, `iphone`→`ios`), события сортируются по `(cookie_id, event_ts)`. Признаки строятся только по событиям внутри окна `[window_start_ts, window_end_ts)`.

**Признаки (95), таргет не используется:**

| Группа | Что описывает |
|---|---|
| Активность | счётчики и доли типов событий, энтропия типов, конверсия в контакты и избранное |
| Тайминг | интервалы между событиями (среднее, медиана, квантили, CV), всплесковость, доля мгновенных переходов, сессии, часы активности |
| Разнообразие | число уникальных объявлений, категорий, локаций, запросов, повторные просмотры, энтропия категорий |
| User-Agent | семейство браузера, ОС, версия, признак headless (строка целиком не используется) |
| Курсор | разброс координат, доля точек на границе экрана, шаг между точками, уникальность позиций |
| Популярность | сколько других кук смотрели те же объявления и запросы в день окна и за 6 предыдущих дней |
| Прочее | платформа, глубина поиска, капча, вход в аккаунт, возраст куки |

**Валидация.** Тест лежит позже трейна по времени, поэтому валидация тоже временная: 3 фолда, обучение на окнах строго до границы, проверка на следующих трёх днях. Метрика считается официальной функцией `precision_at_recall` из `metric.py`.

**Модель.** `HistGradientBoostingClassifier` (усреднение по 10 seed) + `ExtraTreesClassifier`; перед смешиванием score переводятся в ранги, веса 2:1.

## Результаты валидации

Финальный blend, по фолдам:

| Валидация | P@R≥0.7 | PR-AUC | ROC-AUC | Ботов в фолде |
|---|---|---|---|---|
| 2026-04-11 … 04-14 | 0.7692 | 0.7867 | 0.9378 | 199 |
| 2026-04-14 … 04-17 | 0.8107 | 0.8261 | 0.9566 | 195 |
| 2026-04-17 … 04-20 | 0.8485 | 0.8113 | 0.9458 | 160 |
| **Среднее** | **0.8095** | **0.8080** | | |

Ход улучшения решения (средний P@R≥0.7 по тем же 3 фолдам):

| Конфигурация | P@R≥0.7 |
|---|---|
| Baseline из quickstart (RandomForest на `n_events`, `n_unique_items`) | 0.0962 |
| Базовые признаки после очистки событий (HGB) | ≈ 0.699 |
| Все группы признаков (HGB) | ≈ 0.777 |
| Финальный blend (HGB × 10 seed + ExtraTrees) | 0.8095 |

Baseline и финальный blend считаются в `solution.ipynb` (раздел 4) на одних и тех же фолдах. Две промежуточные строки (≈ 0.699 и ≈ 0.777) получены в экспериментальном ноутбуке, который в репозиторий не входит.

Baseline по фолдам: P@R≥0.7 = 0.0932 / 0.0996 / 0.0957, PR-AUC = 0.2318 / 0.2295 / 0.1634. Это на уровне доли ботов в train (≈ 8%), то есть почти константа; финальное решение улучшает метрику примерно в 8 раз.

## Ограничения

- В каждом фолде 160–199 ботов, поэтому метрика заметно шумит между фолдами (0.77–0.85); отличие от результата на скрытом тесте (0.888) тоже находится в пределах такого разброса.
- Признаки популярности используют события других кук (в том числе тестовых) за день окна и 6 предыдущих дней, но без таргета. Они считаются по календарному дню `window_start_ts`; специальная проверка выровненности окон по суткам не проводилась. В первые дни выборки скользящее окно короче, чем у последних.
- Границы экрана для признаков курсора заданы константами 1920×1080, для мобильных платформ это приближение.
- Веса blend 2:1 подобраны вручную.
- Байтовое совпадение `submission.csv` при перезапуске проверено в одном окружении; на другой платформе или с другими версиями библиотек возможны минимальные расхождения чисел с плавающей точкой.

## Запуск

Python 3.12.0.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt jupyter
```

1. Скачайте данные и положите `train.csv`, `test.csv`, `events.csv.gz` в папку `data/`. Файл `metric.py` должен лежать в корне репозитория рядом с ноутбуком.
2. Выполните `solution.ipynb` сверху вниз: `jupyter nbconvert --to notebook --execute --inplace solution.ipynb`.
3. Ноутбук создаст `submission.csv`. В разделе 7 он заново обучает модель, сохраняет `submission_rerun.csv` и сравнивает MD5 двух файлов, а затем записывает `requirements.txt` с версиями текущего окружения.

Воспроизводимость: `SEED=0`, `early_stopping=False`, однопоточное обучение (`n_jobs=1`, `threadpool_limits(1)`), версии библиотек зафиксированы в `requirements.txt`.

## Использованные инструменты

pandas, numpy, scikit-learn, scipy, threadpoolctl (open-source, запускаются локально). Большие языковые модели и внешние API не использовались. Функция фильтрации событий по окну построена на основе кода из quickstart организаторов.
